## Problem

An AI that writes interfaces produces inaccessible output by default. This is not a
tuning problem. Models optimise what they are rewarded for — a render tree that looks
correct — and semantic structure is invisible in that signal. The defect is intrinsic and
it is therefore permanent across every generator, not a bug one vendor will fix.

The tooling that exists to catch this is uniformly **advisory**. Audit servers, linters,
PR-time scanners: each reports findings to an agent that is entirely free to ignore them
and declare itself done. In an agent loop, an advisory checker is a suggestion.

That is the whole problem in one sentence: **the thing being checked is also the thing
deciding whether the check mattered.**

## Research

I did not commission a study. I watched models work against an advisory checker and
recorded how they behaved, which turned out to be the more useful method — the failures
were not what a survey would have surfaced.

Models do not fail because they lack the rule. They satisfy the letter of the check and
miss its purpose:

- Told a page needs visible text, they add text that is off-screen, transparent, or one
  pixel tall. A word-count check reading `innerText` passes it.
- Told contrast must pass, they place text over an image, where contrast is
  *undeterminable* rather than failing — and an "incomplete" result is not a violation.
- Told a canvas needs a text alternative, they add one and leave the canvas as the only
  real content on the page.

Each of these is a rule-follower's answer. That reframed the design problem: the checker
does not need to be smarter, it needs to be **unbypassable**, and it needs to know the
specific ways its own checks get satisfied without being met.

## Trade-offs

The advisory scanner was the obvious build and I rejected it. What shipped instead makes
finishing itself conditional: the model *requests* completion, and the harness adjudicates
that request against a fresh audit. If anything changed since the audit ran, the audit is
stale and the request is refused. Budget exhausted, wall-clock exceeded, iteration cap hit
— every exit path fails closed. There is no path where the model marks its own work done.

The costs I accepted, plainly: generation is slower; some designs that are genuinely fine
get rejected as unverifiable rather than wrong; text over a canvas is refused outright
even when a human can see it reads perfectly. That last one is a real design-quality cost
and I still think it is correct — an unverifiable pass is indistinguishable from a lie,
and the entire value of the gate is that it never emits one.

## Outcome

All 52 sites are published in this portfolio's gallery, and the distinction between them
is stated on every card rather than blurred: **17 came out of the engine**, where the audit
*was* the gate and it could not finish until the page passed; **35 are hand-authored** on a
shared scroll-story runtime, and their receipt is an independent re-audit of the shipping
code rather than a gate the generator had to clear.

Collapsing those two into one claim would have been easy and would have read better. It
would also have been the precise failure this work exists to argue against — which is why
provenance is derived from the artefact itself rather than asserted in prose.

Each receipt was regenerated against the copy that actually ships rather than inherited
from an earlier claim. The source project's own documentation asserted persisted reports
for 35 sites when only 9 existed on disk.

The reports are deliberately narrow. Every one names **seven criteria it did not
evaluate** — keyboard traversal, reflow, input purpose and others that axe has no
automated rule for. A conformance report that lists its own blind spots is worth more than
one that implies completeness, and after the FTC's action against automated-overlay
vendors, "we verified everything" is a claim nobody should make.

## Retrospective

The gate is not the moat and I would not build it first again. A competent team
reimplements the refusal mechanism in a fortnight. What took real observation is the
enumeration — knowing that models reach for transparent filler text, that "incomplete"
is where unverifiable contrast hides, that a decorative canvas becomes the whole page.
That list is the artifact; the gate is just how it gets delivered.

The second thing I would change is scope discipline in the UI. An early version of the
interface described its live grade as *provably matching a real audit*, when the honest
claim is narrower: equal to the audit on the statically-decidable subspace, never more
lenient elsewhere. For a project whose entire argument is proof rather than promises, an
overclaim in its own interface is the failure it opposes, in miniature. I caught it in my
own copy, which is the only reason I trust myself to catch it elsewhere.
