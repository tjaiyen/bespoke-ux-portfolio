## Problem

Twenty-six deterministic finance tools, each individually correct, are not automatically
something a person can operate. The naive next step — a page per tool — produces twenty-six
tabs nobody opens in order, and answers a question nobody actually walked up asking. A
controller does not open a dashboard wondering what `ap_three_way_match` has to say today.
They open it wondering **what needs my attention**, across everything.

That reframes the build entirely. The problem is not "visualize this tool's output" run
twenty-six times. It is **information architecture**: what is the smallest surface that gets
someone to the right finding, from any starting point, in the time they actually have.

## The entry point is the findings, not the tools

The front door is a single findings feed, aggregated across all twenty-six components and
sorted worst-first — critical, then serious, then warning, then the positive ones. Every row
names its source tool and links straight to it. That ordering is the whole design decision: it
answers "what needs my attention" directly, and a reviewer only has to go tool-by-tool once
they already know which tool matters right now.

## Interview Mode, and the mistake it was built to avoid

A first-time or time-boxed viewer does not need thirty-two sections; they need five that
actually demonstrate the pattern. That is Interview Mode — a toggle that collapses the sidebar
and the page to a five-tool walkthrough.

I built the hand-maintained version once already, on this same portfolio — a hardcoded route
list quietly dropped pages from an accessibility audit four separate times before it was
replaced with one that walks the filesystem. Interview Mode was the second time I hit the
identical shape of bug, and this time I recognized it before shipping it: two lists that are
supposed to agree will eventually stop agreeing, so there should only ever be one list.

The guided tour gets the same discipline applied in the other direction: it forces Full
Dashboard mode before it starts, specifically so every one of its 32 stops stays reachable
regardless of which mode the page happened to load in. A tour that can silently walk into a
section Interview Mode has hidden is the same bug wearing a different hat.

## What "measured" means on this specific page

Every figure — the finding counts, the pass/fail badges, the KPI tiles — is transcribed from a
real, deterministic run of the underlying tool against synthetic sample data. Nothing is
composed for display, and the page says so in its own disclaimer footer rather than leaving it
implied. That distinction matters more here than almost anywhere else in this portfolio: a
dashboard is the easiest kind of artifact to fake convincingly, because a screenshot of
plausible numbers looks identical to a screenshot of real ones. The only way to tell the
difference is to say plainly which one you're looking at, and I would rather a reviewer doubt
me and check than trust me and be wrong.

## Outcome

One surface over twenty-six tools: a worst-first findings feed as the entry point, a full
32-section dashboard one click away, a five-tool Interview Mode derived from the same data the
full nav uses, palette and density controls, and a scoped `⌘K` search across every tool and
finding.

## What I would change

**The findings feed has no way to say "I've seen this, stop showing it."** Worst-first sorting
is right for a first look and wrong for a returning user who has already triaged yesterday's
criticals — right now they re-read the same list every time, and the feed has no memory of
what has already been acted on. That is a real gap between a demo surface and an operations
tool someone uses daily.

**Interview Mode is a good answer to "what should a stranger see first," and a weaker one to
"what should today's on-call controller see first."** Those are different questions — one is
about a fixed introduction, the other is about what changed since the last time someone
looked — and I built the first because it was the one I could ship, not because I had decided
the second one mattered less.
